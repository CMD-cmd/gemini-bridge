---
name: gemini-bridge-view
description: 查看已有 Gemini Bridge 任务的状态、交付与验收，使用聊天内只读任务卡片或完整详情页。适用于已有 job_id 的任务，不创建或重试生成。
---

查看前运行 `python3 "<BRIDGE_ROOT>/script/check_cli_update.py"`。有输出时在当前或最终回复简短转述一次，无输出继续查看；每日检查与提醒跨聊天去重，后台刷新不消耗待发提醒。此步骤只查 CLI 更新，不生成、不升级，失败不影响查看。


优先用已配置的 Gemini Bridge HTTP MCP 的 `bridge_native_panel(job_id=原任务编号)` 返回原生详情卡片。它直接读取已有记录；“查看详情”通过宿主显示模式接口切换到独立面板，不发送聊天消息、不启动额外 Codex 或 Gemini 回合。任务支持任务、进展、结果、检查四个页签。活动任务约每2秒更新实际动作、文件、子任务和最后活动时间；后台或完成待检查约15秒，验收后停止轮询。刷新只读同一任务，不调用模型；没有新事件时不推测百分比或远端心跳。新工具未加载时用 `bridge_task_card(job_id=原任务编号)` 返回旧卡片。它只读已有任务，不创建、取消、重试或改变验收。宿主支持 MCP Apps 时可显示卡片；是否渲染以实际界面为准，工具返回成功不等于宿主已经展示。

已有聊天先以实际工具目录确认新入口；能用就不重连。缺少 `bridge_native_panel` 时先刷新当前聊天，仍缺失再只重连设置中的 `gemini_bridge_http` 并刷新；无需重启 Codex，也不重启其他聊天。磁盘 Skill 更新不等于旧聊天工具目录已刷新，历史旧卡片不会自动升级。

HTTP 工具尚未加载或宿主不支持卡片时，保留同一 job_id，用原生 `gemini_bridge` 的状态工具或同服务客户端读取，再提供 `task_view_url`。需要显示时用 `open_in_codex` 在右侧打开链接；不要为了查看重复提交，也不要重启其他聊天或强行刷新全部连接。

新原生面板通过宿主实际显示模式确认切换；兼容接口可能不返回 mode，要结合 host-context-changed / openai:set_globals 的显示模式事件判断，不能把空返回当作失败。旧卡片“查看详情”仍使用消息中转，可能消耗当前聊天模型的一次回合，只作为备用；MCP ui/message 不能指定本次模型或思考强度，不声称能强制 Luna low，也不因此改变主聊天模型。原网页与卡片内详情继续保留。正文、实际模型与现有验收以原记录为准，请求档位不等于后端独立证明。

要派发新任务，读取已安装的 `gemini-bridge` Skill，仅在当前聊天已有明确Gemini许可时，沿用逐任务材料范围、会员路线和动态选模规则。两档均服从当前聊天许可，不增加单独的高档口令。这个插件不另授予分发权限、不自带模型凭据；复用本机 `gemini_bridge_http` 连接，其凭据由本地 helper 管理。
