## CLI 更新提醒

实际使用 Skill（生成或只读查看）前运行后台 `script/check_cli_update.py`；没有新版或今天已经返回过同一提醒时不输出。需要诊断时加 `--json`。有输出时像普通使用提示一样，在当前或最终回复用一两句转述，不另开聊天回合；不要因为提示而中断原任务或自动升级。

官方发布清单按上海日期每天最多查询一次；同日复用缓存，网络失败也不重复请求。跨进程共享缓存与锁。有新版且仍未升级时，每天首次使用提醒一次；同日本地执行文件变化可单独提示。任务材料、账户凭据不发送给更新服务，检查不调用 Gemini。

本地安装记录的 SHA-256 匹配时沿用该记录；不匹配时，仅运行固定的 `agy --version`，最长两秒，并把结果与当前二进制指纹一起缓存，不修改原安装证据。`local_identity=cli_version_probe` 是执行文件自报版本，不等同于下载包来源验证；仍无法识别时保持 `installed_version=null`，不能从官网版本猜测本机版本。

`cli_update.notify=true` 才转述 `cli_update.notice`。只读 `bridge_status` 和旧卡片自动刷新只准备提醒，`notification_pending=true` 不消费每日提醒；原生 `bridge_native_panel` 会把待发提醒透传给 Codex，Skill 检查脚本、其他直接工具及同服务命令行使用同一去重记录，避免漏传或重复。

这是使用时提醒：没有使用 Bridge 时不会后台唤醒聊天。检查失败不让任务失败、不改变模型与会员路线。用户要求升级时，再检查是否空闲、备份旧执行文件并验证兼容性；不根据远端输出自行执行命令。

## 右侧任务详情页

每次提交、状态查询、结果读取或验收返回若有 `task_view_url`，在当前聊天提供简短的“查看任务详情”链接，提交与交付都指向同一 job_id；不要向主聊天粘贴完整原始日志。工具返回的 `viewer_url` 是本地任务历史入口。`viewer_error` 只表示查看器暂不可用，不代表 Gemini 执行失败，不因此重新提交任务。

用户要求查看或当前交付需要展示时，先检查本聊天实际工具目录：有 `bridge_native_panel(job_id)` 就优先使用新原生详情面板，后续按钮直接切换宿主视图，不发送消息、不启动额外模型回合。新工具未加载或原生面板不可用时，才备用原网页、旧 `bridge_task_card` 或 `open_in_codex(target={type:"browser",url:task_view_url},placement="right")`；旧卡片的消息中转可能消耗当前聊天模型回合，需明确说明。不要随轮询反复打开页面。模型执行和验收仍走现有桥接工具；查看不授予任务分发权限。

已有聊天以实际工具目录确认新入口，不能假定已经同步。缺少 `bridge_native_panel` 时先刷新当前聊天；仍缺失再只关闭并重新打开设置中的 `gemini_bridge_http`，然后刷新该聊天。已能调用新工具就不重复重连，无需重启 Codex，也不重启其他聊天。磁盘 Skill 更新不等于旧聊天工具目录已经刷新，历史消息中的旧卡片保留原行为。不要通过重交 Gemini 任务验证展示。

本地备用命令：`python3 client.py view --job-id <任务编号>`（工作目录为上述后端），只生成或恢复本地查看器链接，不启动 Gemini。详情页读已有记录，显示完整返回内容、提交的实际指令、所选附件副本、运行进度及现有验收说明；格式化阅读与原文均可查看。模型/档位显示来自记录，实际模型来自运行证据；档位仅有请求配置时如实标注。

实时活动／子任务视图、运行中纠正和中断观察恢复见[实时控制](realtime-control.md)。前台活动约 2 秒、后台／完成待验收约 15 秒刷新，不调用模型。

## 型号查询异常

`authentication` 表示认证检查未通过，不能仅凭此判定已退出登录、会员失效或额度不足；CLI 刷新令牌时的网络中断也可能表现为认证错误。先读诊断原因：`catalog_network`、`catalog_timeout` 属于连接问题；`catalog_access_denied` 表示访问被拒，单独的 403 不是重新登录的充分证据。明确的 invalid_grant、令牌撤销等才按凭据问题处理。

生成前的失败不记作 Gemini 交付失败，也不宣称产生了结果。无 job_id 的型号查询失败，会在私有 `.runtime/catalog-diagnostics/<diagnostics_id>.json` 保存原始诊断和时间；已有任务沿用其 catalog-diagnostics.json。只提取必要错误原因，不向聊天粘贴令牌、账户标识或原始诊断全文。连接恢复后可以重新做零生成的目录查询，不使用过期目录放行；v0.13 后台按账户、CLI 与网络身份复用最多 15 秒的新鲜观测并合并同时查询，刷新失败立即失效，不降级到旧数据；已有失败任务是否补试按下文有限重试判断。

## 状态与等待

分别理解三类等待：目录／状态的短查询、watch观察窗口、CLI生成上限。目录查询仍最多约45秒、客户端单次请求最多55秒；这些不随高档模型变慢而整体拉长。原生MCP查询没收到回复不能据此判断模型生成失败，先查同服务客户端；已知连接异常时可直接用备用客户端，不能为“等回复”重复提交。bridge_run_text兼容接口总观察窗口30秒（包含其提交耗时），未完成返回原job_id供后续查询；高档一律使用受控scope和bridge_submit异步交接。

提交后保留 job_id，使用 bridge_status。返回的 `progress` 来自本地CLI已有事件、stderr和进程探测，可看到排队/初始化、工具调用、开始输出、整理结果、明确超时等阶段，以及耗时、预计等待、最长保护、当前余量、最近有效进展和已观察到的完成工具数。它不返回原始思考、工具参数或材料。工具数只按读到的事件计算；event_history_truncated=true 时不是完整历史计数。

CLI自身print超时可能以exit=0及SUCCESS回传部分结果；`progress.cli_print_timeout=true` 或 requires_attention=true 时先核对原因，不能把SUCCESS视为完整交付。旧state/report保留，progress提供补充诊断。report存在也可能是失败报告，正文/内容验收仍另查；已accepted应同时看state.review或progress.review。

`no_recent_stream_activity=true` 表示超过该任务快照中的静默提示阈值仍未收到新流式事件：低档默认90秒；高档low／medium／high默认180／300／420秒。旧任务没有快照时保留90秒。它不是失败或取消条件，不能称云端卡死，也不能以静默为由重新生成。`local_process_exists=true` 只证明该PID存在；provider_status=not_exposed_by_cli 表示没有远端心跳或后台运算状态。process_missing、超时、等待权限、明确错误需说明实证；不自动授予权限或修改模型；能否补试按下文有限重试判断。

等待期间先做独立工作；无需每秒让Codex查询。可由Codex运行同服务本地等待命令：

```sh
python3 "<BRIDGE_ROOT>/client.py" watch --job-id <任务编号> --wait-seconds 30
```

它最多进行一段0—60秒的本地查询循环，完成即返回，未完成则回传当前进度；不提交任务、不调用模型、服务断开时不自动拉起后台。查询窗口结束不会取消CLI任务；预计预算与最长保护以requested-profile.json.waiting_policy为准，动态截止以progress.effective_deadline_seconds为准。需要继续等待再决定下一段，至少60秒内向用户交代进展；显示无活动时如实说状态不确定。短查询失败不等于Gemini任务失败。

取消与重试是不同动作：取消后确认终态；失败先保存原报告和证据。续接conversation或向stdin发新消息会启动新一轮执行，不能用作只读状态查询。重试遵循下文有限重试；用户另有限制时从其更严格限制。

新任务使用事件驱动等待：timeout_seconds是预计预算，配置在model-routing.json.waiting，不绑定模型名称。低档按复杂度默认180／300／600秒，高档按所选思考强度默认600／900／1200秒；可在本档上限内明确调整，最小10秒。超过预计预算不立即取消：同一进程、同一会话的新正文增量、新步骤及工具完成/报错可延长观察，低档进展宽限120秒、高档300秒；没有进展时仍有有限静默宽限。重复事件、文件修改时间、PID存在不当作远端心跳。CLI最长保护低档600秒、高档1800秒，本地另留最多30秒退出余量；不无限延长或以续接代替重试；终态失败按下文有限重试判断。旧任务保留原快照和固定等待语义。

progress.waiting_mode、soft_budget_exceeded、wait_reason、meaningful_events和observed_generation_state帮助解释等待，右侧详情页同步显示。provider_status=not_exposed_by_cli时无法确认云端是否仍在思考；官方交互TUI的statusline状态不是已核实的headless心跳。读取暂时失败不终止模型，继续有限观察。时间从CLI进程实际启动计算，排队与目录／身份／账户预检不计入；多个聊天共用单worker，各自范围、材料、预算与取消独立。

## 有限重试

普通生成任务由 Codex 协调，同一逻辑任务最多 3 次尝试（首次加最多 2 次重试），沿用当前聊天已有许可，无需逐次重问。后台记录根任务、父子重试链、尝试序号及每轮 job_id／request_id；每个新 job／request 都计入上限，包括未启动 provider 的失败。重传同一 request_id 或恢复同一任务不是新尝试；新建 scope、换 ID、重启或切换通道均不能重置该逻辑任务的计数。用户限制更严格时遵守；完成或用户关闭即停止，关闭 scope 不复活。

先用 `bridge_summary`／`bridge_status` 读取原任务终态、错误原因及正文／文件，保留本轮报告和诊断。仅在明确网络故障、目录查询超时、暂时服务错误或额度错误，且正文为空、没有文件交付、执行已明确停止时，才可补试。额度错误不承诺恢复可用额度，也不切换账户或 API。认证、地区、权限或身份冲突、用户取消、已有正文／文件交付、运行中及结果不明均不自动重试；静默、短查询断开、观察窗口结束和展示失败不构成生成失败。空正文、格式或合同错误、拒绝动作及越界工具使用本身也不是可重试原因。达到上限或不符合条件时保留已有产物，由 Codex 接着处理并报告缺口。

工作区任务可能已经执行命令或写文件，不自动重做已启动 provider 的 workspace 生成；只有确证 provider 未启动的 workspace 预检失败，且原因符合上述条件，才允许补试。无法确认是否启动时停止补试。

符合条件时调用 `bridge_retry(job_id=原失败任务编号, thread_id=当前聊天)`；再次失败须先读取新任务再决定下一次，不循环盲重交。重试保持原模型、effort、提示、验收要求和材料快照；所选附件须与原快照一致，变化则停止；目录任务重新核对 scope 记录的目录身份和权限，不通过重试扩大材料范围。thread_id 必填并须与原提交聊天一致；每轮重新核验当前身份、仍有效的原 scope 和材料，不修改原记录，不自动重新启用已关闭的历史 scope。对同一父 job 重复请求返回已有子任务，不创建新一轮、不重置计数；下一次重试必须指向最新失败子任务。

旧聊天没有 `bridge_retry` 工具时，直接使用同服务受控客户端，无需为工具缺失重新取得生成许可：

```sh
python3 "<BRIDGE_ROOT>/client.py" retry --job-id <原失败任务编号> --thread-id <当前聊天ID>
```

取得每个新 job_id 后立即调用已加载的 `bridge_native_panel(job_id)` 展示该轮原生卡片，客户端补试也一样；工具未加载时按上文恢复展示或提供同任务链接，不为卡片重复生成。保留每轮独立证据和关联编号，不覆盖失败记录。后台只执行受控重试请求，不自行发起生成重试。

生图不使用普通任务的 3 次流程重做整批：仍仅对每张明确失败的图片按原提示、原参考图补试一次，成功图不重做；详见[生图流程](image-generation.md)。

## 验收与用量

`completed_unreviewed` 和原生 `SUCCESS` 只证明执行结束。对照事实、证据位置与输出要求按内容核对：保留没有问题的部分，局部问题由 Codex 修订或请 Gemini 解释／修改后复验。`bridge_review` 支持 accepted、accepted_with_changes、partially_accepted、revision_requested、rejected；note 写简短具体理由，可选 accepted_items、issues、changes 保存采用与修订范围，多轮记录保留历史。执行状态与内容采用分别记录，不把格式小问题扩大为整份拒绝，也不把未核验事实标为通过。细节见[交接与续聊](delegation-workflow.md)。后端没有独立报告推理档位，不能把启动参数称作后端档位证明。

状态工具的紧凑结果预览最多 6000 字符，完整报告与原始事件留在本地；这是展示预算，不是模型输出长度限制或任务默认字数目标。先读紧凑结果，需要时再读完整报告；等待阶段做独立工作，不频繁轮询、不转述原始日志。一次失败先定位，按有限重试处理。取消后确认终态。

回传的 `bridge_version` 是实际执行核心版本，`mcp_adapter_version` 是调用适配器版本；文件里写了新版本不代表旧进程已加载。适配器按请求加载当前实现，客户端拒绝版本不匹配的旧后台。宿主已缓存的工具目录新增参数仍需重新连接；不要将本地协议验证称作原生聊天验证。

后台排队和本地 GUI 的轮询不调用 Codex 模型。分解、复核、整合仍使用 Codex；Gemini token 不能换算为 Codex 订阅额度节省百分比。只有有对照的实际用量证据才能宣称减少了多少额度。

## 规则同步与旧工具说明

实际执行读取共享后台当前配置，普通查看、status/review 和已有任务卡片不需开启生成。账户路线沿用现有登录，不再执行 `/settings` 核验 `useG1Credits=false`，也不检查或覆盖账户 credits 开关。历史任务若报该预检错误，保留原始失败记录；读取状态、刷新或更新 Skill 不会自动重发生成。当前聊天没有明确 Gemini 许可时，两档生成默认关闭；有许可时 authorization 记录用户原话，两档共用，不要求另点名 高档推理模型。Ultra 本地次数与固定时效限制保持取消。若旧聊天工具目录仍写“高档必须额外点名 高档推理模型”或旧次数，先读磁盘现行 Skill 与 bridge_task_mode 的实际 reason，不用旧说明推断不可用。工具元数据更新需刷新对应聊天／MCP 连接；已经能正常调用时无需重连。只刷新该聊天，仍旧再重连 gemini_bridge_http，不重启 Codex 或打断其他聊天。

ACP 执行器断线或缺少终态证据时，先用原 job_id 观察／恢复；未收到文字也不证明远端没有生成，不据 EOF 自动重发。明确的暂时性RPC失败和生成前目录故障仍按最多3次规则处理。
