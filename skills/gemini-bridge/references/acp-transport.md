# 通道与同会话续聊

v0.13 已验证默认路由和稳定工作区续聊；材料 ACP、headless 工作区和生图通道继续保留。

`transport="auto"` 按执行服务已开放能力选通道：材料和普通工作区优先 ACP；带原生子任务的工作区及生图使用 headless。未经资格开放的能力沿用既有通道或明确拒绝，不改参数绕过门禁。明确指定通道时保留选择；失败后先查原任务，不切通道重复生成。模型／effort 仍由实时目录、任务需求及现行策略动态选择。

ACP 直接发送文本与所选图片；工作区沿用 scope、任务 broker、原件保护与受保护结果，MCP 仅注入本任务选定服务，保留 `inheritMcp:false`。材料任务不因 ACP 获得目录、命令或 MCP 权限。型号证据是会话目录与配置回执，不是独立后端追踪。

## 续聊

`bridge_submit(continue_job_id=上一轮job_id, ...)` 只发本轮增量，后台从已核对记录取得 session，不接受裸 provider ID。保持原通道、模型和 effort；每轮有独立 job、request_id、交付和验收。不并发分支，只从最新轮继续。

新 ACP 工作区使用 host 管理的稳定 session cwd，每轮重新绑定工作区授权；上轮 worktree 作为本轮输入，再建立独立副本，历史交付不原地改写。路径或许可不能安全接续时使用新会话。旧版本无稳定 cwd 的工作区和带 native child 的会话不自动升级为可续聊；用新任务与必要的已验收产物接续。生图保持逐图流程。

每轮需要有效 scope，覆盖此前共享材料。已关闭 scope 不复活，历史上下文不是新权限。运行中纠正、观察恢复与重试分别见[实时控制](realtime-control.md)和[有限重试](operations.md#有限重试)。

## 取消与活动

ACP 取消发送 `session/cancel`，分别记录本地原因与真实 stopReason。只有对应取消回执才标记协议确认；未知、EOF、end_turn 不替代取消 ACK。思考通知只保存无正文活动计数，没有通知时不推断远端思考。关闭后保留本地证据及可用上下文。
