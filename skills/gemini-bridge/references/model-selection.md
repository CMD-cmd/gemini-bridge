## 动态模型选择

本任务首次需要选模、用户指定型号、账户/CLI变化或怀疑型号不可用时，先用 `bridge_models`（本地备用为 `client.py models`）读取官方 CLI 的实时目录，不从 Skill 内置一个型号列表。后端执行每个任务前也会核实所请求型号仍在目录中。目录可包含不同 Gemini 代际、Flash及其他推理模型和各档位；未来新型号只有实际出现在目录后才视为可选，不能根据传闻构造模型标识。

`profile.json` 是手动调用的默认值。Codex先判断任务的用途、所需推理深度和允许的模型分档，再从实时目录与策略允许的交集中选具体型号与档位，成对填写model/effort并用selection_reason记录简短理由。没有需要覆盖建议的理由时可省略两者，由后端按model-routing.json的保守建议选择；查看model_selection。明确指定的组合不静默替换。

实时目录证明“账户列出该型号”，不证明生成一定成功、额度充足或自动派遣已获准。`policy.json.external_models` 和会员成本例外属于独立的、已有证据支持的映射；新型号可能已在目录出现但尚未分类。此时如实区分可连接与自动分发资格，不称其不可用，不以 manual 绕过门禁。需要增加新型号或映射时维护仓库内的 routing/policy.json，并核实同版证据与安装者的明确选择，不在普通任务里猜测其能力/成本或改写组合。

## 按任务动态选模与思考强度

`bridge_models` 实时读取账户目录，并返回当前路由配置与已映射候选。模型ID保存在配置和policy中，Skill不固定型号。普通候选以AA证据筛选；限定用途专用模型额外记录用户授权、调用记录及尚未核验的能力项。普通任务不联网重算或自行添加评测映射；未来模型出现后，可连接与自动资格分别显示，按模型策略维护流程补入证据即可，无需改业务代码或Skill。

Codex可明确选择model/effort，或省略以采用保守建议，可传 `task_complexity`；下表是默认建议而非强制绑定：

| 任务 | 默认偏好 |
|---|---|
| 字段摘录、规则转换、局部定位、简单检查 | Flash，medium；需要核对时 high |
| 写作、语气、复杂英文表达 | Argon，medium；局部润色 low，多重约束 high |
| 长文阅读、跨文献综合、截图复核 | Argon，medium/high |
| 前端视觉与原型 | Argon，medium/high |
| 生图 | 已验证的 Flash 执行路线 |

`general` 允许 Argon，后端按 kind 与 task_complexity 建议模型族和 effort；copy/english/visual/prototype 中等复杂度起偏好 Argon，extract/code-map 轻任务偏好 Flash，长或复杂阅读偏好 Argon。用途与强度均是建议，不是硬绑定；不为取得 Argon 伪造 task_purpose。材料总字节超过配置长文阈值可提示 complex，但 Codex 应按实际约束判断。以上是当前工作偏好，不宣称官方领域 benchmark 已证明。

复杂后端、数据库、并发、同步恢复、安全、真实动物数据、科研裁决、整合发布仍由当前主 Codex 或合格原生代理承担；Argon 可给独立技术第二意见，本地执行验收由 Codex 完成。候选须实时可用并满足现行资格；普通候选遵守能力上限，已授权外部专用／会员例外仅按策略精确组合生效。公开版附带一份有日期和评测版本的示例映射；它不是最新榜单，也不代表安装者已批准例外。新证据不得混用版本，不编造领域分数。

结果中的 `model_selection` 保存任务复杂度、完整候选原因、所选型号／档位、策略哈希及跨模型族的候选回退。选择其他族或未选首选时，向用户简述原因，不把未选模型宣称为已实际验证。明确指定model/effort时不替换为另一组合，提交前与执行前仍核验政策和账户。

新一代推理模型、Pro与旧Flash的目录及档位会随账户／产品更新而变化；实时目录中消失的型号只保留历史记录，不继续承诺可用，也不以改写名称模拟升级。名称中的产品后缀不决定路由族，`routing_family` 及偏好顺序来自配置。有些型号虽在目录中存在，精确推理档位评测或后端身份仍未核对；普通自动分发按待补映射处理，限定用途专用模型仅凭明确授权例外试用，两者均不应称作CLI连接失败。保留待补原因及原始证据，不能用通用无档位分数冒充具体档位，不能通过手动模式绕过自动分发上限。已核对精确档位也可能因高于当前主模型能力上限而未入选；这与“缺少档位证据”分别说明。新型号不因出现在目录就继承旧型号的会员成本例外、用途例外或生图资格。

## 聊天启用与兼容用途

低高档都以当前聊天用户明确允许使用 Gemini 或主动调用 $gemini-bridge/@gemini-bridge 为入口。未启用时全部由 Codex 处理，订阅资格不代替聊天许可，许可不跨聊天。启用后可在其授权范围内沿用原话，不为 Argon 再请求一次授权；仍逐任务记录 scope、材料和选模依据。用户关闭或指定组合优先，历史 scope 不自动复活或扩权。新范围默认 max_jobs=0、scope_ttl_seconds=null，持续到 complete/disable，Google 服务端额度仍有效。

旧 task_purpose 保持兼容，按实际用途填写；普通任务可保持 general 并选择 Argon。新 scope 用 allowed_purposes 记录涉及用途；历史范围缺字段仍只许 general，不追溯扩权。具体用途、建议强度和账本见 [能力分流与兼容用途](specialist-routing.md)。specialist_budget.limits_enabled=false，保留账本，不按每任务、每日、每周、high 次数或单位数拦截。

失败按[有限重试](operations.md#有限重试)由 Codex 协调，不改选 Flash 绕过同一逻辑任务的次数；生图每张一次补试规则单独适用。等待按实际分档与 effort，保留 Argon 30 分钟、Flash 10 分钟 CLI 工程保护和原动态等待规则。执行前核验当前身份、用途和会员账户路线，禁止 API 回退；不检查或覆盖 useG1Credits，credits 沿用账户设置。账户资格与聊天许可不改变原生代理上限，也不向未来型号自动继承资格。
