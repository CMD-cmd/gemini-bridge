## 生图与补试

`bridge_submit(kind=image, dispatch_mode=auto)` 使用已启用的生图任务模式；`image_count` 指定图片数（默认3，目前1—8），`image_retry_limit` 为0或1（默认1）。这是用户批准的生图失败补试规则：每张图第一次工具调用明确失败后，对相同提示和所选参考图补试一次；补试仍失败即停止本次生图任务。成功图不重复生成，不另建任务绕过计数。普通任务使用[有限重试](operations.md#有限重试)流程，不将该流程叠加到生图或重做整批。

任务服务按所请求张数设置本地权限预算，官方 CLI 的工具前置与后置 hooks 记录每次尝试。只准原生生图、读取所选图片和新生成图片；无命令执行、浏览、普通文件修改或子 Agent 权限。图片输入走现有快照白名单，编辑或参考图任务仍须明确获准分享这些图片。每张输出先经过本地完整解码、尺寸、格式与哈希检查，再保存在 `runs/<job_id>/outputs/`，实际清单在 `generated-images.json`。右侧交付页显示所有回收图，可查看和下载原图；失败任务可能包含已成功的部分图片，仍按实际数量判定。

派任务的模型和档位来自按任务选择、profile或明确成对参数。原生生图工具底层模型由 Antigravity 管理，官方当前文档标注 Nano Banana 2，不能单独选择；未由 CLI 报告时写“实际生图模型未独立核验”，不能把所选 Gemini Flash 型号当生图模型。

仅用现有账户路线，并移除 API 密钥环境变量。credits 沿用账户设置，不调用 `/settings` 核验 `useG1Credits=false`，生图 hook 也不以开关状态或旧的 no_overage_verified 字段作门槛。不宣称实际会员扣减或单张价格已核实。

生图等待默认由profile的image_timeout_seconds决定（默认600秒，低档上限600）；普通文字任务按实际模型分档、思考强度和复杂度设置，明确timeout_seconds在本档上限内优先。模型运行、实际图片回收、内容验收分别记录；图片数量、是否能打开、构图/文字/细节都须核对。失败补试分支可用本地合成事件验证，不为了制造失败另花模型额度。

跨项目架构、真实动物记录、CloudKit/同步恢复、实验设计裁决、科研结论及最终发布由主 Agent 处理。敏感或未授权对外分享的材料不能因为桥接可用而自动发送。

普通外包继续使用AGENTS.md的能力与成本上限；限定用途专用模型按用户批准的external_specialist_exception检查，Argon不再设本地调用次数上限。已建立外部精确组合映射和会员成本例外；是否通过取决于实际主模型、白名单及账户路线，AA 原始成本始终如实记录。用户明确指定交给 Gemini 的范围明确任务可用 manual；这不能替代普通自动分发的任务开关与检查。
