# 能力分流与兼容用途

只有当前聊天用户明确允许使用 Gemini 或主动调用 $gemini-bridge/@gemini-bridge，才按任务自动选择两档。未启用时全部由 Codex 处理，Ultra 订阅不代替聊天许可，许可不跨聊天；启用后无需再单独点名 高档推理模型。模型 ID 保存在实时目录与 policy.json，Skill 不固定型号。主 Codex 结合实时资格、材料、复杂度与验收需求选择 model/effort；用户关闭或指定模型优先。高低档是能力与时延分工，不是许可开关。

写作、语气、复杂英文表达、前端视觉／原型、长文与跨文献阅读、截图复核当前偏好 高档推理模型：medium 为起点，多重约束用 high，局部润色可用 low。字段摘录、规则转换、局部定位和简单检查偏好 低档快速模型 medium/high；生图保留已验证 低档快速模型 路线。这是工作偏好，不是官方 benchmark 已证明的领域排名。

旧 task_purpose 保持兼容；general 也允许 高档推理模型，不为取得型号伪造用途。以下仅建议，不强制绑定模型或 effort：

| task_purpose | 建议 effort | 适合的范围 |
|---|---|---|
| tone_polish | low | 已核对事实的局部语气调整 |
| important_communication | medium | 沟通、审稿回复表达、进度解释 |
| sensitive_communication | high | 分歧、多方诉求或多重表达约束 |
| key_copy | medium | 研究动机、讨论、汇报与产品文案 |
| technical_second_opinion | medium | 有材料的局部方案比较、遗漏与反例 |
| technical_deep_review | high | 多约束技术问题的独立复核意见 |

所有文本／视觉任务共用 [任务控制](task-control.md) 的通用安全工程预算，不另设用途专属输入预算或输出长度目标。长度由任务交付物决定，普通格式仍 advisory。工程预算不是模型 token 容量；实际超出模型容量时明确分阶段并保留关键材料，不静默截断或为预算改写用途。历史 scope 不自动扩权。

## 准备一次有价值的交接

- 交流：原话、目标、已核实事实、希望的关系与语气、不可改变或承诺的事项。返回一个主版本，必要时再给一个短备选。
- 关键文案：目标读者、目的、事实底稿、用户喜欢的风格样例；只送最影响理解的段落，不默认全文重写。
- 技术第二意见：具体问题、相关代码或日志、已尝试方案、约束和需要作出的选择；要求指出证据、遗漏或反例。主Agent实施与测试。

范围明确的实现、调试、测试与界面迭代也可交给低档快速模型 High，不把它限于摘录；多约束子问题可明确选择 XHigh。高档推理模型优先整体方案与复核。多维证据、任务建议与实测范围见[模型能力](model-capabilities.md)，不把旧代际判断直接沿用到新型号。

复杂后端、数据库、并发、同步恢复、安全、真实动物数据、科研裁决、整合与发布仍由主 Codex 或合格原生代理承担。技术第二意见不替代本地执行与验收。这些用途不授予自由工具执行。科研事实与论断强度由主Agent先核对；专用模型不能为文案增加数据或确定性。

## 调用记录与会员额度

新 scope 默认 max_jobs=0、scope_ttl_seconds=null，持续到 complete/disable；用户另行限制次数或期限时遵守。specialist_budget.limits_enabled=false，不按每任务、每日、每周、high 次数或单位数拦截，调用账本仍保留。历史 scope 保持原权限和期限，不自动复活。

Google AI Ultra 不是无限使用，服务端额度仍有效。只走已有会员认证，禁止付费 API 回退；credits 沿用账户设置，不作 Bridge 前置核验；其他客户端用量不计入本地账本。聊天许可不授予敏感数据共享，每项任务仍记录 scope 与材料。

计数跨聊天、跨scope、跨重启共享。排队先预留；已开始生成的失败或取消不退回次数，避免把多次尝试伪作一次。尚未开始的排队取消、预检中断可释放预留；核心进程启动失败或启动前取消有确证时回滚本地计数，不把启动后额度错误当成零启动；零生成恢复仍核验原请求ID及当前余额，不增加任务scope次数。后台重启不重放已开始的调用。这是本地用量账本的记账规则；逻辑任务的尝试计数另按[有限重试](operations.md#有限重试)，每个新 job 均计入，预检未启动也不重置。

专用调用沿用普通任务的[有限重试](operations.md#有限重试)，不通过改选 低档快速模型、新建 ID 或重置 scope 绕过原逻辑任务的尝试上限。每轮保留真实调用记录，已开始生成的失败不退计数；已获准的其他独立任务不因这一次失败被取消。

## 用途例外与运行核验

external_specialist_exception 记录用户授权的精确外部组合与任务范围，general 也可按现行配置使用 高档推理模型；不再把旧用途标签当作获取 高档推理模型 的门票。能力／成本及待补 AA 档位证据按生效策略如实保留，null 不能标成基准核验通过。公开 AA 已到 v5，本地原生上限基线仍为 v4.3.2，本次不重建或混用版本。例外不改变主模型身份核验、原生代理上限、禁派遣名单、材料授权和账户路线，不自动推广到未来型号或生图。

只走现有账号认证，不回退API。所有自动任务（含低档快速模型回退）检查最新回合身份与授权；不再运行/settings核验useG1Credits=false，也不因credits开关未知或开启而阻止生成。最终仍核对CLI报告型号与交付内容，独立后端推理强度没有报告时标为请求档位。

每次从bridge_models或bridge_task_mode读取automatic_specialist_budget时，将其理解为本地调用账本，不是provider剩余额度。选择记录model_selection包含用途、档位、未选原因及预算摘要；需要时给用户简短解释，不粘贴整个账本。


## 慢模型的等待

预计等待按实际模型usage_tier与所选effort判断，和模型ID、用途建议分开。高档low/medium/high默认600/900/1200秒，低档按复杂度180/300/600秒；timeout_seconds可在本档上限内调整。当前mode=activity：超过预计预算不立即终止，同一会话新正文、新步骤或工具状态推进可延长等待。高档进展/静默宽限300秒，低档120秒，CLI最长保护分别1800/600秒，本地最多再留30秒退出余量。静默提示高档180/300/420秒、低档90秒，仅提示不确定性。

排队与预检不占生成时限，从CLI进程启动计时。观察窗口结束或短查询断开不取消原任务，用同job_id继续查询。有进展可继续等；无事件时远端状态未知，PID和重复ACTIVE事件不算心跳。不能以conversation续接来查询状态。达到明确CLI时限或进程保护仍保存部分返回与诊断，SUCCESS不代表完整交付。延长观察不新增自动调用、不修改任务授权。旧任务不改快照。
