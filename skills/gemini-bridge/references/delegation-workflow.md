# 交接与续聊

适用于边界清楚的新委托、返工与诊断。主 Agent 维护轻量契约并直接调用 Bridge，实际参数以当前工具 schema 与已验证实现为准。

## 轻量契约

```text
目标：要查明或完成什么。
完成标准：可观察行为、必要边界情况及交付文件。
入口与目录：少量已确认入口；允许探索、写入和运行命令的目录。
验证：从项目配置确认的测试／检查／构建命令，以及必要的渲染或运行证据。
停止条件：缺少必要材料、需扩权、核心事实无法确认时，保留现有交付并报告；外部执行失败按[有限重试](operations.md#有限重试)判断，无法补试或已到上限时交回 Codex。
```

入口通常给 1–4 个文件作为线索，并非目录搜索的数量上限。缺少仓库事实由执行者在授权目录查找；不猜测命令、接口或结果。诊断与评审引用实际文件位置，区分事实与推断。独立审查只给原始问题和必要材料，避免预先灌输结论。

提示词描述结果和约束，不逐步规定实现。不得顺手扩大改动、删弱测试、提交／推送、安装依赖、部署或上传到新服务；这些动作仍按原任务授权判断。工作区权限、保护路径、独立 worktree 与命令 broker 由 [工作区执行](native-workspace.md) 管理，提示词本身不授予能力。

## 零生成检查与预览

以下接口以当前工具 schema 和实际验收范围为准。预览是可选工具，不是每次提交必经的审批步骤；旧聊天未加载工具时先按现有接口工作。

- `bridge_doctor(refresh=可选bool)`：零模型调用的环境检查。分别报告 CLI 帮助声明、实际入口／版本／文件指纹，以及本地 PTY／stdin-NDJSON 探针；不核验账户认证或会员扣量，也不证明 provider 交互已成功。检查不启用 scope、不提交任务、不安装或登录。
- `bridge_plan`：接受与 bridge_submit 相同的参数，仅校验、选模和展示预览，不占 scope 次数、不排队、不启动 CLI 生成；相同请求已提交时返回 already_submitted 与原 job_id，不恢复或重交。帮助核对输入、权限、路由和待满足条件；不代替提交／执行时的校验，不据此宣称任务可成功生成。
- 缺少工具时按现有只读接口核查，不用真实生成模拟 dry-run，也不为诊断自动改全局配置。

适配器负责通道、参数和状态解析；scope 决定材料及执行权限，resolver／策略决定模型资格。适配器可调用不意味着已有聊天许可或路由资格。保留账户会员路线，禁止 API 回退；credits 沿用账户设置，不核验或覆盖 `useG1Credits`。

## 同会话增量返工

续聊用于同一目标的追问或修正，只发本轮新增事实、差异、失败证据和验收要求。先读取上一轮真实产物，再决定是否续聊；新目标或独立第二意见开启新任务并提供必要背景。

用 `bridge_submit(continue_job_id=上一轮job_id, ...)` 续聊，不接受裸 provider session。只续接同一聊天该会话的最新一轮，且保持同一已核验 model、已记录 effort 请求与执行模式；不并发分支。不能只凭模型自报或猜测 session ID。每轮建立新 job_id 与 request_id，按轮保留卡片、状态、交付及验收；恢复同一轮丢失的响应仍使用该轮原 request_id 与完全相同请求，不混同为下一轮生成。

每轮重新核对有效授权，使用仍有效的原 scope 或有效新 scope。已关闭 scope 不复活；新 scope 必须覆盖此前所有已共享材料，不能通过缩小权限声称历史上下文已被抹去。旧会话中出现过的文件不代表本轮获准读取；未获准覆盖历史材料时开启新会话。用户明确指定模型／档位不得静默改换。

代码续聊的输入目录必须选择上一轮 worktree，新轮再从该输入建立独立 worktree 保留改动；v0.13 ACP 工作区另用稳定 session cwd 与逐轮租约，实际资格见[通道与续聊](acp-transport.md)；不得原地修改上轮已回收证据或源目录。工作区映射、历史材料及实际会话不能安全接续时停止续聊，主 Agent 用已有产物完成剩余工作或另开获准任务。`kind=image` 不开通续聊，跨执行模式也不续接；生图沿用 [生图流程](image-generation.md)，不能据文本续聊推断全场景支持。

运行中纠正与无生成上下文恢复见[实时控制](realtime-control.md)，分别使用 steer 与 recover；它们不替代终态后续聊，也不扩大 scope。

## 分层交付与验收

| 层次 | 平时读取什么 | 何时深入 |
|---|---|---|
| 人读摘要 | 结论、实际改动、产物链接、验证结果、剩余事项 | 每轮交付 |
| 机器状态 | job/request/session 关联、请求与实际模型／档位、执行状态、验收状态、退出码及结构化错误 | 状态恢复或核对执行事实 |
| 原始证据 | 原始返回、事件日志、文件差异／哈希、受保护命令结果与输出 | 异常、来源或边界有疑问时 |

已加载 `bridge_summary(job_id)` 时先读精简结论、交付列表、命令统计与警告；需细节再用 `bridge_status` 或完整 report，原始事件只在诊断时读取。同服务客户端支持 `client.py summary --job-id <编号>`。沿用 Bridge 实际返回的字段和文件，不为套此分层虚构 output_path／result_path／events_path。主聊天不粘贴完整日志，也不强制小任务另建报告。原始返回与采用版本分别保留。

检查实际差异及测试是否被删、跳过或弱化。按改动运行真实验证，UI 验收需查看实际渲染；执行者自写“通过”不等于实跑。broker 的 requested／started／not_started 与受保护 exit_code 优先于自述。阻断的一次工具尝试不自动否定其余交付，实际越界或审计缺失仍须核查。

验收按内容处理，优先判断是否解决任务、事实是否可靠。符合要求且没有问题的部分应保留采纳；措辞、格式或局部缺漏不构成整份拒绝的理由。Codex 可直接做小修订；有实质分歧时先指出具体问题，请 Gemini 解释理由或仅修改相关部分，再结合理由和证据复验。不为个人表达偏好来回返工，不因局部错误重做已采纳内容。

`bridge_review` 支持已采纳 accepted、修订后采纳 accepted_with_changes、部分采纳 partially_accepted、待修改 revision_requested、未采纳 rejected。用简短 note 说明判断，按需附 accepted_items（已采用）、issues（待处理）、changes（修订）；不强制小任务填写所有列表。多轮检查保留历史与原始回复，修订版在主聊天或交付文件中交代。执行异常与内容采用分开记录：可靠的局部交付可以部分采用，原执行错误仍保留；缺失的事实、来源和测试不标为已验证。旧工具仅接受二选一时，使用同服务客户端提交新状态，不把中间结论硬塞成拒绝。

解释或修改属于增量续聊，使用有效材料范围和 continue_job_id，不以失败重试代替；只处理有争议部分。收齐本范围全部任务后关闭 scope，保留交付和证据。
